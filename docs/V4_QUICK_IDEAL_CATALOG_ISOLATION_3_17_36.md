# v3.17.36 — quick ideal catalog isolation

## Цель

Разделить быстрые технические конструкторы и конструкторы линейного сметчика по источнику каталога, не раздваивая саму логику построения.

## Что изменено

- Добавлен `QuickIdealCatalog` — локальная идеальная база для быстрых технических расчётов.
- Быстрые Stage/Truss/LED секции теперь маркируют BOM-строки как `sourceType: quick_ideal` и `sourceSystem: quick_ideal_catalog`.
- `AvailabilityChecker` не сопоставляет `quick_ideal` строки с реальной базой оборудования, не создаёт дефицит и не учитывает резервы.
- В сметчике Stage/Truss/LED продолжают собираться через общий shared-core, но с `catalogMode: quote`, то есть через реальную `EquipmentDatabase`, склад, наличие, резервы и дефицит.
- При передаче быстрого расчёта в черновик сметы `V4QuoteDraftBomSink` пересобирает секции в режиме `quote`, чтобы смета получила реальные складские привязки.

## Важное правило

Шаблоны, построение, визуал, формулы, нагрузки и BOM-правила остаются едиными для quick и quote режимов. Разделён только источник деталей:

```text
quick  -> QuickIdealCatalog -> без склада/дефицита
quote  -> EquipmentDatabase -> склад/резервы/дефицит/субаренда
```

## Что не менялось

- Старый legacy/v3 не возвращался.
- Формулы LED, крепёж, Hanging Bar, PowerCON/RJ45 не менялись.
- Логика нагрузок ферм и визуальные шаблоны ферм не раздваивались.
- Складские движения, резервы и backend controlled writes не затрагивались.
